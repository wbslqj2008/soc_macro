# GitHub 등록과 업데이트 배포

현재 프로젝트는 `wbslqj2008/soc_macro` 공개 저장소를 소스와 업데이트 배포에 함께 사용합니다. `.github/workflows/release.yml`이 `main` 브랜치 푸시를 감지해서 검증, 빌드, GitHub Release 등록을 자동으로 수행합니다. 빌드가 실패하면 새 업데이트를 공개하지 않습니다.

## 처음 등록

저장소 초기 등록은 완료되었습니다. 이후 수정 사항을 배포하려면 PowerShell에서 다음 명령을 실행합니다.

```powershell
cd C:\Users\Admin\Desktop\soc_macro
git add .
git status --short
git commit -m "Update SocMacro"
git push origin main
```

브라우저의 GitHub 로그인과 Git 인증은 별개입니다. 인증 오류가 나면 `git credential-manager github login --username wbslqj2008 --force`로 로그인한 뒤 다시 푸시하세요. `.gitignore`는 빌드 결과, 로그, 개인 설정, 인증 파일을 제외합니다.

## 새 버전 배포

일반적으로는 `main`에 푸시한 뒤 GitHub의 **Actions → Build and publish update**에서 완료 여부를 확인하면 됩니다. 버전은 워크플로 실행 번호를 사용해 `0.1.1`, `0.1.2`처럼 증가합니다. `SocMacro.exe`와 `SocMacro.exe.sha256`이 모두 업로드된 후 정식 릴리스가 공개됩니다. 사용자의 앱은 이 저장소의 Releases를 로그인 없이 조회합니다.

자동 빌드는 Windows 실행 환경과 .NET 9를 사용합니다. 공개 저장소의 소스도 공개됩니다. 나중에 소스를 비공개로 바꾸려면 별도의 공개 배포 저장소와 CI 배포 인증을 구성하고 `UpdateRepository`를 변경해야 합니다.

수동으로 파일을 만들고 싶다면 다음 명령을 사용합니다.

```powershell
cd C:\Users\Admin\Desktop\soc_macro\SocMacro
powershell -ExecutionPolicy Bypass -File .\publish_release.ps1 -Version 0.1.1
```

`soc_macro`의 Releases → Draft a new release에서 버전 태그를 만들고, `SocMacro/publish/`의 `SocMacro.exe`와 `SocMacro.exe.sha256`을 모두 첨부한 후 Publish release를 누릅니다. 정식 릴리스로 공개해야 하며, 초안과 사전 릴리스는 앱에서 무시합니다. 수동 배포 번호는 이미 사용한 번호와 겹치지 않게 정하고, 자동 배포 번호와 혼용하지 않는 편이 좋습니다.

GitHub CLI를 설치하고 `gh auth login`으로 로그인했다면 다음 명령으로 빌드와 배포를 함께 수행할 수도 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\publish_release.ps1 -Version 0.1.2 -Upload
```

처음에는 필수 업데이트 기능이 포함된 exe를 사용자에게 한 번 전달해야 합니다. 이전 선택형 업데이트 버전은 이 정책을 소급해서 적용할 수 없습니다. 이후 앱 실행 시 요청당 최대 5초 동안 새 버전을 확인합니다. 새 버전이 있으면 필수 업데이트 창에서 자동 다운로드와 SHA-256 검증을 수행합니다. 완료 후 **업데이트 후 다시 시작**을 누르면 프로그램이 종료되고 실행 파일을 교체한 뒤 다시 실행됩니다. 새 버전으로 실행해야 로그인과 매크로를 사용할 수 있습니다. 매크로는 자동으로 다시 시작하지 않습니다. 설정과 라이센스는 유지되며 기존 exe는 같은 폴더에 `.previous-...` 백업으로 보관합니다.

**프로그램 종료**를 누르거나 업데이트 창을 닫으면 기존 버전으로 진입하지 않고 종료합니다. 다운로드나 설치 시작에 실패하면 업데이트 창에서 다시 시도할 수 있습니다. 오프라인·서버 오류·공개된 정식 릴리스 없음·잘못된 릴리스 정보로 버전을 확인할 수 없는 경우에도 실행을 허용하지 않으며, **확인**(재시도) 또는 **취소**(종료)를 선택합니다. 다운로드 파일과 오류 기록은 `%LOCALAPPDATA%/SocMacro/Updates`에 저장됩니다. 자동 설치는 배포용 단일 exe에서 지원하며 개발 빌드에서는 다운로드 폴더를 열어 새 exe를 직접 실행해야 합니다.

실행 중에는 주기적으로 업데이트를 확인하지 않습니다. 관리자 권한 안내(UAC)는 Windows 설정에 따라 나타날 수 있습니다.

## 검증

```powershell
dotnet build SocMacro\SocMacro.csproj --no-restore
dotnet run --project tests\UpdaterChecks\UpdaterChecks.csproj
```

실제 배포 전 테스트 PC에서 이전 버전 → 새 버전 다운로드 → 재실행, 업데이트 창 닫기 및 다운로드 실패 시 기존 버전 진입 차단, 오프라인 실행 시 재시도 및 종료를 확인하세요.
