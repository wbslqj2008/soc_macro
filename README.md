# 소오콘 매크로

소드 오브 콘발라리아(PC) 자동화 도구. 현재는 이벤트 **탐험의 여정** 무한 반복을 지원합니다. 일일퀘스트는 준비 중입니다.

## 실행

- GitHub 등록 및 새 버전 자동 다운로드 배포: [업데이트 배포 안내](docs/업데이트_배포.md).

- `SocMacro\bin\Release\net9.0-windows10.0.19041.0\win-x64\SocMacro.exe` 실행 (관리자 권한으로 실행됩니다)
- **F9** 시작, **F10** 정지. 입력 차단 중에도 F10은 항상 동작합니다.
- `SocMacro.exe --autostart`로 실행하면 켜자마자 시작합니다 (작업 스케줄러 예약용).

필요한 것: Windows 10/11, .NET 9 데스크톱 런타임, Windows 한국어 언어팩(OCR).

## 동작 방식

매 순간 게임 화면을 캡처해 어떤 화면인지 판단하고(대부분 Windows 내장 한국어 OCR, 일부는 이미지 매칭), 그 화면에 맞는 버튼을 누릅니다. 그래서 어느 화면에서 시작해도 이어서 진행합니다.

- 좌표는 1274x717 기준이며, 16:9 해상도면 자동으로 비율을 맞춥니다. Windows 배율(DPI)도 자동 처리됩니다.
- 화면 캡처는 게임 창이 다른 창에 가려져 있어도 됩니다. 클릭할 때만 게임 창을 앞으로 가져옵니다.
- 문제가 생기면 `logs\날짜.log`와 `logs\shots\` 스크린샷을 확인하세요.

## 탐험의 여정 흐름

이벤트 → 탐험의 여정 → 탐색 시작/복귀 → 난이도 → 장르 → 맵(이벤트 노드 = 축복 선택, 전투 노드 = 전투 시작 → 배치 → 시작 → 자동) × 7 → 결산(고급 보상/클리어 포인트) → 결과 화면들 → 반복

- 축복: 카드 3장을 OCR로 읽어 키워드 우선순위대로 고름. 제외 키워드가 들어간 카드는 피함.
- 패배: 전투 종료 → 같은 노드 재도전(아군 위치를 무작위 교체). 같은 노드 N패 시 진행도 포기 후 처음부터.
- 행동력 120 미만: 존재의 힘 결정 → 희망의 결정석(하루 한도 설정) → 둘 다 안 되면 자연 회복 대기 (대기 중 입력 차단 해제 가능).

## 일일퀘스트 (출항 → 엇갈린 세계)

- 컨텐츠별 사용 토글. 실전 훈련·진급·뭇별·제작은 횟수(기본 1), 타로·장비·진급·뭇별은 요일별 하위 선택(잠겨 있으면 알림 후 건너뜀).
- 마지막 클리어 스테이지를 소탕. 문어 통조림 사용 옵션(부족하면 계속 소탕으로 채움). 기억 회복은 전투(기존 배치).
- 행동력이 부족하면 대시보드 알림 바에 표시.
- 탐험 중 00시가 지나면 그 판을 마치고 일일퀘스트 → 탐험 반복으로 복귀(설정).

## 글로리 전장 (알림판)

- 일일퀘스트 다음에 진행. 난이도(쉬움/일반/어려움)와 횟수(최대 하루 5회) 설정, 게임의 남은 도전 횟수가 0이면 멈춤.
- 배치 → 시작 → 자동 전투 → 전투 종료/티어 상승 화면 넘기기 → 다음 도전. 화면 인식으로 진행하므로 전투 길이와 무관.

## 라이센스 (Firebase `soc-macro-aq12z`, 소유자 royal9638@gmail.com)

- 실행하면 라이센스 키 입력창이 먼저 뜸. 키가 서버에 있으면 통과(비밀번호·기간·PC 제한 없음). "이 PC에서 키 기억하기"로 다음부터 자동 확인.
- 키 종류: **베이직**(탐험의 여정만) / **프로**(전체) / **관리자**(프로 + 관리자 페이지).
- 매크로 시작할 때마다 서버에서 다시 확인 → 삭제된 키는 그 시점부터 사용 불가.
- 관리자 페이지: **관리자 키로 로그인했을 때만** 보임. 실제 작업은 이 PC의 Firebase CLI 로그인(소유자 권한)으로 수행.
  키 발급(종류/개수/메모/직접 지정, 클립보드 자동 복사), 목록(최근 사용 시각), 프로·베이직 전환, 삭제.
  다른 PC에서 관리하려면 그 PC에서 `firebase login`(소유자 계정) 필요. 관리자 표시는 서버(콘솔/소유자 권한)에서만 붙일 수 있음.
- 서버 규칙: `server/firestore.rules` (배포: `server` 폴더에서 `firebase deploy --only firestore:rules`).
  일반 사용자는 키 하나 조회와 "최근 사용" 시각 기록만 가능. 목록 조회, 종류 변경, 관리자 지정, 키 생성은 불가 (직접 시도해서 거부 확인).
- 한계: .NET 프로그램은 디컴파일로 확인 로직을 우회할 수 있음. 배포 전 난독화 권장.

## 배포용 빌드 (난독화 + 단일 exe)

- `SocMacro` 폴더에서: `powershell -ExecutionPolicy Bypass -File publish_release.ps1`
- 결과: `SocMacro/publish/SocMacro.exe` — 자체 포함(.NET 설치 불필요) 단일 exe, 약 105MB.
- 과정: 빌드 → Obfuscar로 `SocMacro.dll`만 난독화(csproj의 `ObfuscateAssembly` 타깃, `-p:Obfuscate=true`) → 단일 exe로 묶기.
  - 난독화 설정: `obfuscar.xml`. 문자열 암호화(HideStrings)로 Firebase URL·키·모든 문자열을 숨기고, 비공개 멤버 이름을 난독화. 공개 이름은 유지해 WPF(BAML)가 깨지지 않음. 서드파티 dll은 건드리지 않음.
  - 확인됨: 난독화 exe에 Firebase API 키·Firestore URL이 평문으로 없음, 실행·로그인·관리자 기능 정상.
- 난독화 도구: `dotnet tool`(로컬 매니페스트 `.config/dotnet-tools.json`, Obfuscar.GlobalTool). 다른 PC에서 빌드하려면 그 폴더에서 `dotnet tool restore` 먼저.
- 한계: 난독화는 분석을 매우 어렵게 만들 뿐 완전히 막지 못함. 진짜 방어선은 서버 규칙(`server/firestore.rules`).
